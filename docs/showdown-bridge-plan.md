# 官方 Pokémon Showdown 接入计划

当前分支 `feature/showdown-official-bridge` 保留原自建对战服务，并新增官方 Showdown 后端的协议基础层。

实现分为四步。第一步固定后端选择、Showdown id 规范化、packed team 编解码和安全命令构造，并为这些纯逻辑建立契约测试。第二步接入 JDK WebSocket 会话，处理 challenge 登录、队伍上传、官方 validator、排位搜索和好友挑战；每个 PS 战斗房间独立保存请求序号、断线恢复状态和输出顺序。第三步把官方 `|request|`、`|turn|`、`|move|`、`|win|` 等房间输出转换为现有 Cobblemon 镜像战斗输入，把 Minecraft 选择转换为 `/choose`，并沿用临时队伍副本和实体清理逻辑。第四步把客户端入口、配置热重载、状态提示和观战接入现有界面。

可用精灵采用交集规则：`Showdown 当前格式允许集合 ∩ Cobblemon 当前运行时可实例化集合`。形态使用完整 Showdown id 匹配，不能仅按基础物种名放行；招式、能力、道具、等级和队伍结构继续交给官方 validator 判断。这样可以避免不同整合包的独有物种被错误发送到官方服务器。

参考项目暴露的暗坑已纳入边界：官方协议与原自建 TCP/JSON 协议完全不同；Showdown id 会丢弃标点且存在形态后缀；packed team 的空字段不能压缩；官方房间可能在断线后继续计时；远端队伍必须物化为临时副本，不能写回玩家存档；官方服务器的登录断言、速率限制和可用格式由服务器实时决定，不能静态假设。

本文件只记录已经确认的设计和阶段边界。未完成的阶段不会标记为已验证，也不会改变原有 `LOCAL_SERVICE` 行为。
